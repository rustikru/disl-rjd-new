# Единые источники истины

В проекте используются три реестра. Названия, коды, defaults и маршруты нельзя повторять в контроллерах, шаблонах или JavaScript.

## Страницы, права, видимость и меню

Единственный источник: `src/Services/PageRegistry.php`.

Личные и административные страницы имеют разные коды видимости. Например,
`user-report-mailings` («Мои рассылки», группа «Пользователь») и
`admin-report-mailings` («Управление рассылками», группа «Администрирование»)
отключаются независимо. Старый код `report-mailings` поддерживается только как
алиас совместимости существующих настроек и прав и не используется для новых
записей.

Для самостоятельной страницы здесь задаются стабильный код, подпись, URL-префиксы, группа видимости и metadata меню. Из реестра автоматически строятся основное, административное и пользовательское меню, список прав роли, экран `disabled_pages`, а также сопоставление HTTP-запроса с правом.

Чтобы добавить страницу:

1. Добавить одну запись в `PageRegistry::CORE`.
2. Реализовать controller/template и зарегистрировать сам исполняемый маршрут в `src/routes.php`.
3. Не добавлять отдельные списки страниц в middleware или шаблоны.

Отчётные страницы добавляются автоматически из `ReportConfig`; в `PageRegistry` их повторять нельзя. Право `dashboard` управляет только дашбордом: каждый отчёт включается собственной галочкой.

Карточка вагона имеет отдельное право `wagon-card` («Карточка вагона»). Оно
защищает `/wagon`, `/api/wagon/movement` и общий технический API карточки.
Отдельное право отчёта `technical-state` для просмотра карточки не требуется.

## Отчёты, API, фильтры и колонки

Единственный источник: `src/Reports/ReportConfig.php`.

Здесь находятся код и название отчёта, endpoints, PHP handlers, группа/порядок меню, фильтры, detail-колонки, сортировка, экспорт и mailing handler. GET-маршруты отчётов регистрируются из этого реестра автоматически. PHP-шаблон передаёт тот же массив JavaScript, поэтому JS не должен повторять endpoints, подписи фильтров или колонки.

Чтобы добавить отчёт:

1. Добавить определение отчёта, его `apiHandlers`, navigation/page/detail settings в `ReportConfig`.
2. Реализовать указанные методы `ApiController` и SQL/service получения данных.
3. Для нестандартного экрана добавить контейнер `panel-{report-code}` в `templates/app.php`. ID элементов должны совпадать с page settings; это проверяет consistency-команда.
4. Сервер обязан вызывать schema-валидацию фильтров. Клиентская проверка предназначена только для UX и не заменяет серверную.

SQL и повторная серверная проверка безопасности не считаются лишним дублированием: реестр описывает контракт, сервер независимо обеспечивает доступ и корректность входных данных.

Системные коды и семантика `ADMIN`/`SUPER` находятся в `src/Services/Authorization.php`. Контроллеры и шаблоны используют `Authorization::isAdmin()`/`isSuper()`; целевые policy-проверки (например, запрет ADMIN изменять SUPER) остаются на сервере.

`SUPER` имеет безусловный доступ ко всем страницам. Для `ADMIN` страницы не
выдаются автоматически: меню и прямые запросы используют записи его ролей из
`XX_RJD_ROLE_PAGES`. Поэтому «Мой профиль», «Мои рассылки», «Роли»,
«Организации» и остальные разделы доступны `ADMIN` только при установленной
галочке соответствующего права.

«Администрирование» — вычисляемый вход в административное меню, а не отдельное
назначаемое право. Он появляется у `ADMIN` автоматически, если доступен хотя бы
один реальный административный раздел. Страницы `admin_only` нельзя назначить
обычной роли, а страницы `super_only` — любой роли, кроме системного `SUPER`.

Порядок, ключ и исходная подпись 126 колонок справки РЖД находятся попарно в `src/Reports/source-columns.php`. Импорт, whitelist API и исходные XLSX-отчёты читают этот файл через `ReportConfig::sourceColumns()`.

## Конфигурация

Единственный источник типов, defaults, разделов UI и ограничений: `src/Services/ConfigSchema.php`. `rjd_config.php` содержит только значения конкретной установки, а `src/Config.php` применяет схему.

Чтобы добавить параметр:

1. Добавить его в `ConfigSchema::definitions()` с типом, default, разделом, choices/range.
2. Использовать нормализованное значение `$config['key']` без локального `?? default`.
3. Не добавлять поле вручную в шаблон настроек: форма строится из схемы.

`session_lifetime_seconds` одновременно управляет PHP GC, окном Oracle-реестра и подписью страницы активных сессий.

## Проверка согласованности

После изменения реестров выполнить:

```bash
composer check:registry
```

Проверяются уникальность endpoints, существование API handlers, панелей/HTML ID, корректность страниц и схема defaults.
