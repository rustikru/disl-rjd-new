# Перенос SQL в Oracle package

Цель: PHP проверяет права и входные данные, вызывает package и формирует ответ.
Запросы получения и изменения прикладных данных находятся в
`XX_RJD_DISLOCATION_NEW_PKG`.

## Что переносить

### 1. Отчёты

Главный кандидат — запросы из `ApiController`, `ReportService`, `Claims` и
`WagonMovement`. В package должны находиться:

- выборка отчёта и детализации;
- списки значений фильтров;
- сводные показатели;
- сортировка и пагинация;
- выбор актуального среза данных.

Переносить по одному отчёту. Сначала сравнивать результат и время выполнения со
старым запросом, затем удалять SQL из PHP.

### 2. Административные справочники

Страницы пользователей, ролей, групп доступа, организаций, нормативов и станций
можно перевести на функции и процедуры package. Чтение списка удобно возвращать
через pipelined function, изменение — выполнять процедурой.

Права, CSRF и проверка допустимости действия остаются в PHP. Package повторно
проверяет ограничения данных и выполняет операцию одной транзакцией.

### 3. Рассылки

Запросы `MailingService` можно объединить в процедуры сохранения и функции
списка. Это особенно полезно для сохранения рассылки вместе с отчётами и для
регистрации запуска. Переносить после справочников: здесь больше связанных
таблиц и транзакций.

## Что пока оставить в PHP

- проверку подключения к БД;
- первичную проверку наличия таблиц;
- получение прав для middleware;
- технические запросы миграций и диагностики.

Авторизацию и сессии следует переносить последними. Ошибка package в этой части
может закрыть вход во всё приложение.

## Пилот: «Станции и координаты»

Страница полностью использует `XX_RJD_DISLOCATION_NEW_PKG`:

| Операция | Вызов |
|---|---|
| Количество | `stations_count` |
| Страница списка | `stations` |
| Одна станция | `station` |
| Сохранение | `save_station` |
| Удаление | `delete_station` |

PHP содержит только SQL-оболочки для вызова package и передачу bind-параметров.
Прямых запросов к `XX_RJD_STATIONS` на этой странице нет.

## Требования к следующим переносам

1. Поддерживать Oracle 11: не использовать `OFFSET ... FETCH`.
2. Передавать значения только через bind-параметры.
3. Не получать все строки для пагинации в PHP.
4. Не выполнять отдельный вызов package для каждой строки результата.
5. Сохранять ограничение данных по текущей организации.
6. Сравнивать количество строк, значения и порядок со старой реализацией.
7. Измерять отдельно время Oracle и полное время HTTP-запроса.
8. Спецификацию и тело package устанавливать вместе с изменением PHP.
