# Пользовательские KPI

## Назначение

Пользователь может создавать простые личные карточки только на страницах «Подход вагонов» (`approach_kpi`) и «Отправление вагонов» (`departue_kpi`). На первом этапе карточки доступны только создавшему их пользователю. Системные KPI остаются общими и не редактируются через конструктор.

## Хранение

Пользовательские и системные карточки находятся в `XX_ETW.XX_RJD_KPI_TBL`. Для пользовательских карточек используются `PAGE_CODE`, `OWNER_ID`, `IS_SYSTEM = 'N'` и `WHERE_CONFIG CLOB`. Условия хранятся как JSON, а не как SQL. Для системных карточек `IS_SYSTEM = 'Y'`; их условия остаются в `XX_ETW.XX_RJD_DISLOCATION_NEW_PKG.GET_KPI_WHERE`.

ID новых карточек выдаёт `XX_RJD_KPI_TBL_SEQ` через триггер `XX_RJD_KPI_TBL_BI`.

## Формат условий

```json
{
  "operator": "AND",
  "conditions": [
    {"field": "depart_station", "operator": "LIKE", "value": "Ейск"},
    {"field": "cargo_weight_kg", "operator": ">", "value": 0}
  ]
}
```

JSON разбирается PHP-классом `src/Reports/KpiCondition.php`. Класс разрешает только поля конкретной страницы, проверяет типы и операторы, формирует SQL с bind-параметрами. Произвольные имена колонок, SQL и функции из JSON не принимаются. Для `LIKE` пользователь вводит текст поиска, приложение добавляет шаблон поиска.

## API

- `GET /api/kpi/user/catalog?kpi_type=...` — список доступных полей.
- `POST /api/kpi/user` — создание или изменение своей карточки; обязательны CSRF-токен, название, тип страницы и конфигурация.
- `DELETE /api/kpi/user/{id}` — удаление только своей пользовательской карточки.
- `GET /api/kpi/summary` — дополнительно возвращает личные карточки для выбранного типа KPI.
- `ApiController::dislDetail()` применяет сохранённые условия при открытии детализации и проверяет владельца.

Владелец берётся из `$_SESSION['user']['id']`, а не из запроса. Работа конструктора ограничена организацией MTF.

## Разрешённые поля

Список централизован в `KpiCondition::fields()` и `KpiCondition::compile()`. Сейчас используются поля станций отправления/назначения и операции, груза, рода вагона, состояния, индекса/номера поезда, веса, даты операции, нормативной даты доставки и остатка расстояния. Набор зависит от страницы.

## Ограничения первого этапа

- Только простые плоские условия с объединением `AND` или `OR`.
- От 1 до 10 условий, длина значения до 200 символов.
- Показатель — количество вагонов.
- Нет пользовательских формул, группировок и публикации другим пользователям.
- Системные KPI не переводятся на JSON и остаются в PL/SQL.

## Изменения БД

Миграция `db/kpi/2026-11-06-user-kpi.sql` добавляет поля, ограничение и индекс, последовательность и триггер. Её применение в Oracle 11 выполняется отдельно; наличие изменений в установленной БД этим архивом не подтверждается.

## Действия в карточках

После загрузки KPI кнопка добавления располагается последней в ряду карточек. Её нажатие обрабатывается делегированным обработчиком документа, поскольку `showKpi()` перерисовывает содержимое контейнера и удаляет обработчики элементов, назначенные непосредственно кнопке. Кнопка восстанавливается после события `kpi:rendered`.

У личных карточек отображаются действия редактирования и удаления. Редактирование открывает тот же конструктор с загруженными названием и JSON-условиями; сохранение передаёт ID существующей карточки в `POST /api/kpi/user`. Системные карточки таких действий не имеют.
