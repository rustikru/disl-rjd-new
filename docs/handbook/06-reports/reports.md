# Отчёты, фильтры, таблицы и экспорт

## Единая конфигурация отчётов

`src/Reports/ReportConfig.php` — основной реестр отчётов. `ReportConfig::all()` возвращает определения, в которых могут быть:

- имя отчёта;
- endpoint фильтров, summary и detail;
- фильтры и их типы;
- измерения/grouping dimensions;
- настройки колонок;
- API-обработчики;
- навигация и настройки страницы;
- обработчик для рассылки;
- вкладки и колонки детализации.

`ReportConfig::forContext('page')` и `forContext('mailing')` отбирают определения для конкретного сценария. `find()` ищет отчёт по коду. `validateFilters()` нормализует и проверяет фильтры.

## Как API отчётов попадает в маршруты

В `src/routes.php` цикл проходит по `ReportConfig::all()`, читает `api_handlers`, находит endpoint нужного типа и регистрирует GET-маршрут. Перед вызовом метода `ApiController` вызывается `ReportConfig::validateFilters()`.

Это означает, что при добавлении отчёта нужно согласовать три части:

1. конфигурацию отчёта;
2. реальные методы `ApiController`;
3. frontend, который использует endpoints и ключи фильтров.

## Основные API-пары

Для отчётов обычно используются три вида endpoint:

- `filters` — доступные даты, грузы и другие варианты фильтра;
- `summary` — сводные значения и группировки;
- `detail` — строки выбранной детализации.

Не у каждого отчёта есть все три endpoint: например, техническое состояние и контроль простоев могут иметь только detail/filters, согласно конфигурации.

## Колонки и подписи

- Конфигурация отчётных колонок — `ReportConfig.php`.
- Исходные подписи/метаданные — `source-columns.php`.
- Конфигурация структуры карточки вагона — `WagonConfig.php`.

Стабильные ключи колонок используются в коде и в пользовательских настройках. Не меняйте ключ только ради изменения отображаемого названия.

## Персональная настройка таблиц

`TableLayoutService` читает и сохраняет расположение колонок пользователя и отчёта. При сохранении сервис проверяет, что ключи входят в разрешённые колонки отчёта, добавляет пропущенные допустимые колонки и сохраняет порядок/закрепление в транзакции.

Таблицы:

- `XX_RJD_TABLE_LAYOUTS`;
- `XX_RJD_TABLE_LAYOUT_COLUMNS`.

DDL — `db/2026-11-04-table-layouts.sql`.

## Экспорт

В архиве присутствуют:

- `src/ExcelExport.php`;
- `src/Excel/ExcelStyle.php`;
- `src/Controllers/ApiController.php::exportVirtualTable()`;
- `ApiController::exportMatrixTable()`;
- `public/assets/js/excel-export.js`;
- `public/assets/js/csv-export.js`.

API маршруты:

- `POST /api/export/vt-table`;
- `POST /api/export/matrix`.

Серверная генерация Excel выполняется PHP-кодом. Клиентские модули отвечают за экспорт данных/таблиц на стороне браузера. Точный набор используемых PHP-библиотек нельзя подтвердить без `composer.lock`.

## Как добавить отчёт

1. Найдите похожее определение в `ReportConfig::all()`.
2. Добавьте код и параметры `self::report()`.
3. Укажите фильтры и типы/значения по умолчанию.
4. Укажите summary/detail/filter endpoints, которые реально реализуете.
5. Добавьте методы в `ApiController` и SQL с bind-параметрами.
6. Убедитесь, что источники данных ограничены активной организацией и областью данных.
7. Добавьте колонки в реестр, подписи в `source-columns.php`.
8. Проверьте frontend, таблицу, детализацию и экспорт.
9. Проверьте `PageRegistry` — отчётная навигация строится из `ReportConfig`.
10. Запустите `composer check:registry`, PHP lint и ручную проверку API.
