# Формы, POST, JavaScript и оформление

## Где находится frontend

- `public/assets/js/app.js` — основной frontend-файл приложения; в архиве около 73 КБ.
- `public/assets/js/page-visibility.js` — работа с видимостью страниц.
- `public/assets/js/detail-contexts.js` — контексты детализаций.
- `public/assets/js/data-scopes.js` — интерфейс областей данных.
- `public/assets/js/mailing-run.js` — действия запуска рассылки.
- `public/assets/js/excel-export.js`, `csv-export.js` — экспорт на клиенте.
- `public/assets/js/wagon.js` — логика карточки вагона.
- `public/assets/css/app.css` — общие стили приложения.
- `auth.css`, `wagon.css` — отдельные стили.

В проекте также присутствуют локальные библиотеки jQuery, Chart.js и Leaflet.

## Как проходит AJAX-запрос

Типичный сценарий:

1. Пользователь меняет фильтр или нажимает кнопку.
2. JavaScript собирает значения формы/контекста.
3. Отправляет `fetch` на URL API.
4. Slim направляет запрос в соответствующий метод `ApiController`.
5. Сервер проверяет параметры и доступ, читает Oracle.
6. Контроллер возвращает JSON.
7. JavaScript обновляет таблицу, карточку или блок страницы.

Перед добавлением нового обработчика найдите похожий вызов в `app.js`, `data-scopes.js` или другом профильном файле. Сохраняйте принятый формат JSON и обработку ошибок.

## POST-действия

Для POST обязательны:

- CSRF-проверка;
- серверная проверка права;
- проверка допустимости ID и принадлежности объекта;
- валидация всех значений;
- bind-параметры в SQL;
- безопасный ответ без текста SQL/stack trace.

В `routes.php` некоторые POST-обработчики вызывают методы контроллеров, другие обрабатывают действие в callback. Независимо от формы регистрации маршрута безопасность должна быть серверной.

## Общие элементы интерфейса

`AGENTS.md` требует использовать существующие классы `app.css`: `ui-page-head`, `ui-page-title`, `ui-panel`, `ui-card`, `ui-table`, `ui-fields`, `ui-field`, `ui-form-actions`, `btn`, `ui-back-link` и другие существующие компоненты.

Правила:

- новая страница визуально повторяет ближайшую существующую страницу;
- форма должна быть компактной (`ui-form-page`, `ui-page-head--form`);
- кнопки действий выравниваются в одну линию;
- повторяющиеся стили не копируются в `<style>` шаблона;
- локальный CSS допустим только для уникальной детали;
- проверяются длинные названия, пустое состояние, ошибки, read-only и узкий экран.

## Работа с таблицами

В проекте есть `TableLayoutService`, который сохраняет персональное расположение колонок по пользователю и коду отчёта. Ключи колонок должны совпадать с колонками, определёнными в `ReportConfig`. API:

- `GET /api/table-layout/{reportCode}` — получить состояние;
- `POST /api/table-layout/{reportCode}` — сохранить;
- `POST /api/table-layout/{reportCode}/reset` — сбросить.

Схема таблиц описана в `db/2026-11-04-table-layouts.sql`. Состояние сохраняется в `XX_RJD_TABLE_LAYOUTS` и `XX_RJD_TABLE_LAYOUT_COLUMNS`.
