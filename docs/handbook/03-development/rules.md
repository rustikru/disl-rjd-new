# Правила безопасной разработки

Этот раздел основан на корневом `AGENTS.md`, который обязателен для разработчиков и ИИ.

## Сначала изучить соседний код

Перед изменением:

1. Прочитайте весь метод и соседние похожие реализации.
2. Найдите использование метода по проекту.
3. Проверьте единый реестр, который владеет соответствующей настройкой.
4. Сделайте минимальное изменение, решающее задачу.
5. Не форматируйте весь файл ради небольшой правки.

## Имена

- PHP-классы — `PascalCase`.
- Методы и переменные — `camelCase`.
- CSS-классы — `kebab-case`.
- Коды страниц и отчётов — `kebab-case`.
- Булевы переменные начинаются с `is`, `has` или `can`.
- Используйте короткие понятные английские имена.

## Безопасность

- Все входные данные проверять на сервере.
- SQL выполнять с bind-параметрами, не склеивать SQL из пользовательских значений.
- HTML-вывод экранировать через `htmlspecialchars()`.
- POST проверять по CSRF, праву и допустимости объекта.
- Не считать скрытую кнопку защитой.
- Не показывать пользователю пароли, SQL, stack trace и конфигурацию.
- Не записывать секреты в журнал.

## Ошибки

Неожиданное исключение журналируется через `ErrorLogger::logThrowable()`, даже если контроллер перехватывает его и преобразует в безопасное сообщение. Пользователю показывается сообщение и код `ERR-...`.

Ошибки ожидаемой валидации пользовательских данных не нужно записывать как технические исключения.

## Единые реестры

| Что меняется | Где менять |
|---|---|
| Страницы, маршруты прав, меню, видимость | `src/Services/PageRegistry.php` |
| Отчёты, API endpoints, фильтры, колонки | `src/Reports/ReportConfig.php` |
| Исходные подписи колонок | `src/Reports/source-columns.php` |
| Структура карточки вагона | `src/Reports/WagonConfig.php` |
| Параметры, типы, defaults, ограничения | `src/Services/ConfigSchema.php` |

Не дублируйте определения в контроллерах, JS и шаблонах.

## Проверки

```bash
php -l путь/к/изменённому.php
node --check public/assets/js/изменённый.js
composer check:registry
git diff --check
```

После изменения прав обязательно проверьте прямой URL без права, работу с правом, POST/API, отключение страницы и внешний вид.

## PROD

Вносите изменения через контролируемое развёртывание. Не запускайте старые SQL-файлы из `db/old/` без анализа. Не применяйте миграцию, пока не выяснены её зависимости, повторяемость, права и влияние на существующие данные. Сравнивайте тест и PROD и фиксируйте, какие SQL-объекты действительно применены.
