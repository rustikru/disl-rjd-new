# Работа с Oracle

## Подключение

`src/Database/DbFactory.php` создаёт реализацию `DbInterface`. Основной класс — `src/Database/OracleDb.php`. Он использует OCI8 и настройки из нормализованного массива конфигурации.

`src/Config.php` загружает внешний `rjd_config.php`, затем передаёт массив в `ConfigSchema::normalize()`. Значимые ключи Oracle:

- `db_host`;
- `db_port`;
- `db_name`;
- `db_user`;
- `db_pass`.

Реальные значения в документацию и Git не помещать.

## Контракт DbInterface

| Метод | Назначение |
|---|---|
| `fetchAll($sql, $params)` | Все строки SELECT как массив |
| `fetchOne($sql, $params)` | Первая строка либо `null` |
| `page($sql, $params, $offset, $limit)` | Выборка с пагинацией |
| `execute($sql, $params)` | INSERT/UPDATE/DELETE; число затронутых строк |
| `beginTransaction()` | Начать транзакцию |
| `commit()` | Зафиксировать транзакцию |
| `rollback()` | Откатить транзакцию |

Сервисы должны по возможности зависеть от `DbInterface`, а не напрямую от OCI8. Это упрощает повторное использование и тестирование.

## Пример SELECT с параметром

```php
$row = $this->db->fetchOne(
    'SELECT id, name FROM xx_rjd_organizations WHERE id = :id',
    ['id' => $organizationId]
);
```

Параметр `:id` связывается с переданным значением. Не вставляйте пользовательское значение в SQL через конкатенацию.

## Пример изменения данных

```php
$changed = $this->db->execute(
    'UPDATE xx_rjd_example SET is_active = :active WHERE id = :id',
    ['active' => 1, 'id' => $id]
);
```

Имена таблиц/колонок обычно нельзя безопасно передавать как bind-параметры. Если динамический SQL необходим, допустимые имена выбирайте только из жёсткого белого списка.

## Транзакции

Пример используемого в `MailingService` подхода:

```php
$this->db->beginTransaction();
try {
    // Несколько согласованных операций записи.
    $this->db->execute($sql, $params);
    $this->db->commit();
} catch (\Throwable $error) {
    $this->db->rollback();
    throw $error;
}
```

Не подавляйте исключение после rollback: верхний уровень должен обработать и записать техническую ошибку.

## Даты

В SQL проекта часто применяются `TO_DATE(:date, 'YYYY-MM-DD')`, `TO_CHAR(...)`, `TRUNC(...)`, `SYSDATE`. Перед сравнением даты выясните тип колонки и часовой пояс, в котором приложение формирует дату.

В переданном архиве `src/Config.php` не задаёт `date_default_timezone_set()`. Поэтому нельзя утверждать, что PHP использует `Asia/Yekaterinburg`: часовой пояс зависит от PHP-конфигурации/окружения и должен быть проверен отдельно.

## Организационный контекст и области данных

`Organizations` загружает доступные организации пользователя, выбирает активную и формирует SQL-фильтр. В проекте также есть `db/data_scopes/`: правила доступа по организации, грузу, станции назначения и вагону. README описывает Oracle VPD через `DBMS_RLS` и функцию `XX_RJD_DISLOCATION_NEW_PKG.DATA_SCOPE_PREDICATE`.

Важно: скрипты в `db/data_scopes/` описывают порядок включения, но факт включения VPD в конкретной базе требует проверки.

## Диагностика

1. Проверьте наличие OCI8: `php -m | grep -i oci8`.
2. Проверьте параметры подключения, не выводя пароль.
3. Выполните простой `SELECT 1 FROM dual` в SQL Developer.
4. Сравните SQL и bind-параметры, сформированные приложением.
5. Найдите код ошибки в `tmp/log/errors/`.
6. Проверьте права пользователя БД и наличие/валидность Oracle-объектов.

Для SQL-отладки есть `QueryLogger`, который включается при `app_debug`. Не включайте подробный SQL-журнал в PROD без необходимости: запросы могут содержать чувствительные параметры.
