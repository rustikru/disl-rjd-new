# Маршруты, авторизация и права

## Где объявляются URL

Все маршруты снимка архива находятся в `src/routes.php`. Приложение использует Slim:

```php
$app->get('/login', $callback);
$app->post('/login', $callback);
$app->group('/api', $callback);
```

Для API отчётов используется цикл по `ReportConfig::all()`: endpoint и имя метода контроллера берутся из конфигурации отчёта. Поэтому добавление нового отчёта обычно не требует вручную добавлять каждый API URL в отдельный список маршрутов, но нужно правильно заполнить конфигурацию и реализовать методы.

## Каталог страниц

`src/Services/PageRegistry.php` — основное место, где описаны:

- код страницы;
- подпись;
- связанные маршруты;
- группа видимости;
- пункт меню;
- административная навигация;
- скрытые/унаследованные права;
- общие маршруты API.

`PageRegistry::all()` объединяет базовый список `CORE` с отчётами из `ReportConfig::all()`. Поэтому отчёт с настроенной навигацией попадает в каталог страниц автоматически.

## Как проверяется доступ

`PageAccessMiddleware` определяет страницу для URL через `PageRegistry`, загружает разрешения пользователя из таблиц ролей и применяет правила `PageRegistry::forUser()`.

Правила из `AGENTS.md`:

- `SUPER` имеет безусловный доступ ко всем страницам;
- `ADMIN` не получает автоматический доступ только из-за названия роли — права идут из назначенных ролей;
- если нет администратора, в коде предусмотрен режим первичной настройки с открытым списком страниц;
- скрытие ссылки в меню не является защитой маршрута;
- WEB, POST и API должны проверяться на сервере.

Для общих API существует `PageRegistry::SHARED_ROUTES` и метод `accessPages()`. Разрешающие права для общего endpoint должны быть описаны явно.

## Видимость страницы — не то же самое, что право

Глобальное отключение страниц реализовано через `PageVisibility` и таблицу `XX_RJD_DISABLED_PAGES` (DDL в `db/2026-11-02-page-visibility.sql`). Это отдельный механизм от назначения прав ролям.

Упрощённо:

- **право** отвечает на вопрос «может ли этот пользователь открыть функцию?»;
- **видимость** отвечает на вопрос «доступна ли функция в приложении вообще?»;
- **меню** отвечает на вопрос «показывать ли ссылку пользователю?».

## Организационный контекст

`OrganizationMiddleware` использует `Organizations`. Сервис загружает организации пользователя, выбирает активную организацию и устанавливает контекст Oracle через `DBMS_SESSION.SET_IDENTIFIER`/`CLIENT_INFO` — точные вызовы смотрите в `src/Services/Organizations.php`.

Не формируйте фильтр организации вручную, если для этого уже есть `Organizations::filter()`.

## Безопасное добавление права

1. Выберите отдельный стабильный код страницы в `kebab-case`.
2. Добавьте страницу и её маршруты в `PageRegistry`.
3. Защитите WEB и API middleware.
4. Для POST отдельно проверьте CSRF и право на конкретное действие.
5. Если маршрут общий, добавьте явное правило в `accessPages()`.
6. Проверьте доступ с ролью, без роли, под `SUPER` и прямым URL.

Подробная процедура — [добавление страницы](../03-development/adding-page.md).
