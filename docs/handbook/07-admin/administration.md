# Административная панель

## Где находится реализация

- Маршруты — `src/routes.php`.
- Основной контроллер — `src/Controllers/AdminController.php`.
- Пользователи — `UserController` и `AdminController`.
- Области данных — `DataScopesController`, `DataScopes`.
- Настройки — `SettingsController`, `ConfigSchema`.
- Сессии — `SessionsController`, `SessionRegistry`.
- Рассылки — `MailingController`, `MailingService`.
- Шаблоны — `templates/admin/`.
- Навигация — `PageRegistry::ADMIN_NAVIGATION` и `templates/partials/admin-sidebar.php`.

## Разделы, видимые в коде

В `PageRegistry` определены административные страницы:

- пользователи;
- роли;
- группы доступа;
- области данных;
- организации;
- настройки приложения;
- видимость страниц;
- технические работы;
- управление рассылками;
- активные сессии;
- журнал действий;
- информация о системе.

Дополнительные справочники маршрутизируются через `/directories`: нормативы, станции, контроль простоев и причины простоя.

## Пользователи и роли

Права пользователя строятся через назначенные роли и коды страниц. Роль не должна считаться автоматически привилегированной только по подписи. Специальные проверки `SUPER` выполняются через `Authorization`.

Для новой административной функции:

1. Определите отдельный код страницы/права.
2. Добавьте маршрут в `routes.php`.
3. Добавьте определение в `PageRegistry` и пункт в `ADMIN_NAVIGATION`, если он должен отображаться в меню.
4. Защитите маршрут middleware.
5. В POST-операциях повторно проверяйте действие на сервере.
6. Добавьте шаблон в `templates/admin/` и используйте общие стили.
7. Для неожиданных ошибок примените `ErrorLogger`.
8. Проверьте пользователя без права, обычного ADMIN и SUPER.

## Области данных

`DataScopes` управляет доступными областями. SQL и правила описаны в `db/data_scopes/README.md`.

Правила в README:

- одна строка правила объединяет организацию AND груз AND станцию назначения AND вагон;
- пустые дополнительные поля означают любое значение;
- разрешающие строки объединяются OR;
- затем исключаются совпавшие DENY;
- учитываются активные области и действующий период;
- пользователь без разрешений получает пустую выборку, SUPER — полный доступ.

Включение Oracle VPD — отдельная операция с SQL-скриптами и проверкой производительности. Не считать её выполненной только потому, что код/DDL лежат в Git.

## Настройки приложения

`ConfigSchema` задаёт тип, default, секцию, допустимые значения и ограничения. Настройки включают окружение, debug, base path, параметры БД, LDAP/Kerberos, рассылки, сброс пароля, сессии и журналы.

При добавлении настройки изменяйте `ConfigSchema::definitions()` и связанный UI/сохранение. Не добавляйте произвольный ключ без нормализации.

## Видимость и технические работы

- `PageVisibility` использует `XX_RJD_DISABLED_PAGES`.
- `MaintenanceMiddleware` и `Maintenance` проверяют режим технических работ.
- Настройки технических работ включают флаг, начало/окончание, заголовок и текст.

В `ConfigSchema` проверяется, что конец периода позже начала. Production требует включённый secure cookie.

## Аудит и сессии

`AuditLog` записывает административные действия. `SessionRegistry` синхронизирует сессии, хранит состояние и позволяет отзывать их. Для входа/выхода и управления сессиями смотрите соответствующие вызовы в контроллерах и маршрутах.
