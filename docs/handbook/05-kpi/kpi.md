# KPI-карточки и расчёты

## Откуда берутся карточки

По реализации `ApiController::kpiSummary()` карточки читаются из представления `XX_RJD_KPI_TBL_V`. Основной запрос вызывает табличную функцию пакета:

```sql
SELECT kpi.id, kpi.code, kpi.type, kpi.label AS x_label,
       t.x_value, t.trend_pct, t.trend_dir
  FROM XX_RJD_KPI_TBL_V kpi,
       TABLE(xx_rjd_dislocation_new_pkg.get_kpi_row(kpi.id)) t
 WHERE ...
 ORDER BY kpi.order_by
```

Если основной запрос завершается ошибкой, PHP пробует альтернативные варианты с `set_kpi_label()`, `fnc_get_kpi_trend_pct()` и `fnc_get_kpi_trend_dir()`, а затем вариант только со значением. Это резервирование находится в `ApiController::kpiSummary()`.

## Цепочка KPI

1. `templates/app.php` содержит каркас дашборда.
2. `public/assets/js/app.js` запрашивает API `/api/kpi/summary` и строит карточки.
3. `src/routes.php` направляет запрос в `ApiController::kpiSummary()`.
4. Контроллер получает организационный фильтр через `Organizations::filter()`.
5. Для MTF выполняется запрос к `XX_RJD_KPI_TBL_V` и Oracle-пакету.
6. Результат преобразуется в JSON-массив `sections[].values[]`.
7. Для карточек, имеющих конфигурацию `ReportConfig::kpiDetail()`, формируется контекст детализации.

Для организаций, отличных от MTF, текущий код возвращает пустой набор значений KPI: `sections => [['values' => []]]`. Это конкретное поведение данного снимка кода.

## Формат данных карточки

В JSON для обычного KPI формируются поля:

- `id` — ID записи KPI;
- `value` — рассчитанное значение;
- `label` — подпись или специальное название из `ReportConfig::kpiDetail()`;
- `detail` — контекст и параметры перехода;
- `trend` — направление динамики;
- `change` — процент изменения.

Точное визуальное оформление нужно смотреть в `public/assets/js/app.js` и `public/assets/css/app.css`; не следует считать, что каждый KPI обязан иметь все элементы (например, динамику может не вернуть резервный SQL).

## Особый тип: KPI погрузки

Если query-параметр `kpi_type=loading_kpi`, метод `kpiSummary()` вызывает `loadingKpiSummary()`.

Алгоритм:

1. Контроллер строит исходную выборку методом `loadingFrom()`.
2. Получает карточки типа `loading_kpi` из `XX_RJD_KPI_TBL_V`.
3. Для каждой карточки `loadingPeriodCondition()` создаёт условие по коду.
4. Условия считаются через `COUNT(CASE WHEN ... THEN 1 END)`.
5. В JSON для карточки передаётся контекст `loading` и `loading_period`.

Поддерживаемые коды:

| Код | Период |
|---|---|
| `loading_today` | С начала сегодняшнего дня до начала следующего |
| `loading_yesterday` | Вчерашний календарный день |
| `loading_month` | С первого числа текущего месяца до начала завтрашнего дня |

Неизвестный код возвращает условие `1=0`, то есть нулевой подсчёт.

## Обычные KPI и условия

Существующая логика страниц и карточек описана в исходном файле `docs/логика/логика_страниц.md` (в архиве путь был повреждён кодировкой имени). В ней перечислены коды и условия для:

- `dashboard_kpi`: цистерны, остальные вагоны, гружёный транзит, подход к УГЛ, прибытие на УГЛ;
- `departue_kpi`: направления и брошенные поезда;
- `approach_kpi`: направления, нарушение срока доставки, брошенные/сформированные поезда;
- `loading_kpi`: периоды погрузки.

Условия KPI находятся в Oracle-пакете `XX_RJD_DISLOCATION_NEW_PKG`, в частности в логике `get_kpi_where` по существующей документации и исходникам пакета. Перед изменением обязательно сверяйте актуальную спецификацию и тело пакета.

## Как добавить KPI

1. Согласуйте смысл показателя и точное правило подсчёта.
2. Определите, к какому типу относится KPI (`type`) и в каком разделе он показывается.
3. Подготовьте/согласуйте запись в `XX_RJD_KPI_TBL` и доступное представление `XX_RJD_KPI_TBL_V`. Схема этой таблицы в архиве полностью не описана.
4. Для обычного KPI добавьте/измените соответствующее условие в Oracle-пакете и проверьте компиляцию.
5. Для KPI погрузки используйте поддерживаемый код и при необходимости расширьте `loadingPeriodCondition()`.
6. Если карточка должна открывать специальную детализацию, добавьте конфигурацию в `ReportConfig::kpiDetail()` и серверную выборку.
7. Проверьте значение SQL-запросом на контрольной выборке и сравните с детализацией.
8. Проверьте отображение, подпись, динамику, пустое значение и права доступа.
9. Обновите `docs/логика/логика_страниц.md` и эту главу.

Нельзя добавлять карточку только в JS: серверный источник, код KPI и условие расчёта должны быть согласованы.
