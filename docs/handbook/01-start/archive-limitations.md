# Ограничения переданного архива

Документация составлена по файлам `Архив.zip`. В архиве есть PHP-код, шаблоны, frontend-ресурсы, SQL-пакеты, часть миграций и существующая документация. Некоторые необходимые для полного воспроизведения приложения файлы отсутствуют.

## Что отсутствует

| Отсутствующий компонент | Почему важен | Что нужно получить для полной проверки |
|---|---|---|
| `rjd_config.php` | Реальные настройки БД, LDAP, окружения, путей и почты | Обезличенный пример конфигурации с сохранением ключей и типов |
| `composer.json`, `composer.lock` | Список и версии PHP-зависимостей | Оба файла из корня проекта |
| `vendor/` | Фактические версии библиотек | Устанавливается Composer по lock-файлу; не требуется передавать целиком, если есть lock |
| часть `bin/` | В `routes.php` есть подключение `bin/downloads_mail_rjd.php` | Каталог `bin/` из актуального проекта |
| конфигурация cron / службы планировщика | Нельзя подтвердить, как запускаются периодические задачи на сервере | Crontab/systemd-конфигурация без секретов |
| полная baseline-схема Oracle | Многие таблицы упоминаются кодом, но DDL не входит в архив | DDL или результаты диагностических скриптов `db/rjd/` |
| установленное состояние Oracle | Наличие SQL в Git не означает его применение | Результат проверки объектов и версий на тестовой БД |

## Важное расхождение по рассылкам

В этом архиве `MailingService::dueMailings(DateTimeInterface $dateTime)` выбирает активные рассылки с `send_time = текущая минута` и проверяет дату последнего запуска. В архиве не обнаружен класс `MailingScheduler` и CLI-файл `bin/run-mailings.php`.

Следовательно, обсуждавшаяся в другой версии логика «подхватывать все просроченные рассылки за сегодня» в данном архиве не подтверждается. Не переносите на этот снимок код и выводы из последующих локальных правок. Для документации и проверки PROD нужен актуальный `MailingService.php`, CLI-скрипт и конфигурация планировщика именно из той версии, которая развёрнута.

## Другие ограничения

- `src/Config.php` загружает внешний `rjd_config.php`, но сам часовой пояс в этом файле явно не задаётся.
- `bin/downloads_mail_rjd.php` подключается маршрутом, но отсутствует в архиве.
- SQL-файлы в `db/old/` обозначены как старые миграции. Не следует запускать их без проверки истории установки.
- SQL-пакеты в каталоге `db/` — исходники пакетов, но их успешная компиляция на PROD не подтверждена.

## Что запросить для следующей ревизии

1. Актуальный архив проекта с `bin/`, `composer.json` и `composer.lock`.
2. Обезличенный `rjd_config.example.php`.
3. Текущую конфигурацию cron/systemd для всех фоновых задач.
4. Вывод `db/rjd/01_inventory.sql` и `db/rjd/02_columns.sql` с тестовой БД.
5. Подтверждение, какие миграции и версии пакетов применены на PROD.
