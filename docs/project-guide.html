1. Назначение и возможности

Приложение показывает состояние и движение вагонов по организациям на основе Oracle-таблицы XX_DISLOCATION_RJD. Оно строит сводные и подробные отчёты, карточку движения вагона, KPI, карту, претензии и нормативы; импортирует справки РЖД из XLSX; управляет пользователями, ролями и организациями; экспортирует таблицы в Excel; сохраняет пользовательские задания рассылки и позволяет вручную сформировать их файлы.

Данные

Дислокация, подход, отправление, погрузка, простои, сырьё, техсостояние, претензии, анализ периода.

Управление

Пользователи, роли, права страниц, организации, станции и нормативы.

Вывод

HTML/JSON, карта, ручной XLSX и подготовка XLSX-файлов рассылки в файловую папку.

Текущая граница системыАвтоматический запуск по расписанию и SMTP-отправка не реализованы. Поля расписания хранятся, но исполняются только при ручном запуске через web-интерфейс.

  1. Корневой .htaccess передаёт запрос в public/; public/.htaccess — в index.php. Для встроенного PHP используется router.php.
  2. public/index.php загружает конфигурацию, включает SQL-log при app_debug, регистрирует ErrorMiddleware и body parsing.

  4. Маршрут выбирается в routes.php. Защищённая группа проходит AuthMiddleware, OrganizationMiddleware, PageAccessMiddleware.
  5. Контроллер читает query/body/files. Часть контроллеров вызывает сервисы; ApiController часто строит SQL непосредственно.
  6. OracleDb bind-ит параметры, приводит имена колонок к lower-case и возвращает массивы.
  7. HTML собирается через ob_start() + include template; API — JSON; Excel — PSR-7 stream.
  8. Необработанная ошибка попадает в ErrorHandler и ErrorLogger.

→

Авторизация

AuthService::login() сначала пробует LDAP, если включён, затем локальный bcrypt-пароль. Kerberos читает principal из server variable либо разрешает локальную имитацию только в development с loopback. Пользователь AD/Kerberos может автоматически создаваться без роли.

Права

Роли связываются с пользователями через XX_RJD_USER_ROLES, страницы — через XX_RJD_ROLE_PAGES. Полный каталог кодов, маршрутов, меню и видимости находится только в PageRegistry. Старое право dashboard разворачивается в отчётные права для совместимости.

Организации

Organizations загружает основную организацию из XX_RJD_USERS.ORGANIZATION_ID и дополнительные из XX_RJD_USER_ORGANIZATIONS. Активный ID хранится в сессии, добавляется во все предметные запросы и передаётся Oracle через DBMS_SESSION.SET_IDENTIFIER. При отсутствии организации фильтр становится 1=0.

Fail-open поведениеPageAccessMiddleware пропускает запрос, если таблицы ролей недоступны, и пропускает всё, пока не найден ADMIN. Это облегчает первичное развёртывание, но опасно при сбое/неполной миграции production.
Единый каталог страниц: PageRegistry. Новую самостоятельную страницу добавляют туда один раз; форма ролей, меню, видимость и middleware используют каталог автоматически.

6. Навигация

Navigation.php только строит результат из PageRegistry. Отчётные пункты поступают в каталог из ReportConfig; обычные, административные и пользовательские пункты описываются в PageRegistry.

Новый отчёт меняется в ReportConfig. Новая самостоятельная страница — в PageRegistry. Ручные массивы меню в шаблонах запрещены.

ApiController разрешает group-by/column dimensions и поля через белые списки реестра, создаёт bind-параметры для значений, добавляет организационный фильтр и сортировку. Для сводных данных summaryReport() формирует агрегаты и roadTable() — иерархическую матрицу. Подробные методы возвращают rows.

Как добавить новый отчёт безопасно
  1. Добавьте определение в ReportConfig::all(): стабильный code, имя, endpoints, filters, dimensions, navigation.
  2. Укажите PHP handler в apiHandlers(); GET-route зарегистрируется автоматически.
  3. Реализуйте безопасный метод источника/handler в ApiController; примените Organizations, bind-параметры и schema-валидацию фильтров.
  4. Добавьте detail columns/sort и page settings; не дублируйте их в JS.
  5. Для нестандартного UI добавьте панель panel-{code}; её ID проверяет composer check:registry.
  6. Если отчёт годится для рассылки, добавьте реальный detail handler в mailingHandlers().
Одна настройка — несколько потребителейОбщая структура действительно живёт в реестре. Но SQL остаётся в API/сервисах, HTML-поведение — в шаблонах/JS, а Excel-оформление — в ExcelStyle. Это связанные, но разные ответственности.

11. Импорт и защита данных

ImportController принимает только XLSX, читает дату из A2, тип определяет по станции назначения в колонке L, затем сопоставляет 126 колонок с полями XX_DISLOCATION_RJD. Импорт разрешён только для организации с кодом MTF.

upload → системный tmp
→
PhpSpreadsheet, дата/тип
→
BEGIN transaction
→
DELETE старого среза
→
INSERT строк → COMMIT
Защита от безвозвратного удаленияDELETE и все INSERT выполняются одной Oracle-транзакцией. При любой ошибке вызывается rollback, поэтому удалённый срез восстанавливается. Граница замены: дата + type_reference + organization_id.
Остающиеся рискиНет предварительной полной валидации файла до DELETE, проверки числа/названий колонок, лимита строк на уровне приложения и защиты от двух одновременных импортов одного среза. Тип файла определяется бизнес-правилом только для MTF. В сообщении метода упомянута «страница из bin», но соответствующего рабочего файла в проекте нет.

Ошибки приложения

ErrorHandler определяет API по /api/, возвращает JSON с error_id либо шаблон 500. В development добавляет exception/trace.

Файлы логов

ErrorLogger пишет tmp/log/errors/YYYY-MM-DD.log, скрывая известные чувствительные ключи. При debug QueryLogger пишет SQL в tmp/log/sql_debug.log.

SQL debug содержит значения параметровQueryLogger::interpolate() подставляет bind-значения в текст. Не включайте app_debug на production и ограничьте доступ/срок хранения логов.

Часть контроллеров ловит ошибки и показывает flash/JSON самостоятельно (особенно импорт, admin, mailing). 404 имеет отдельный обработчик и шаблон.

15. Запуск

Локально

  1. Установить PHP 8.1+, extensions oci8, mbstring, ldap при AD, а также требования PhpSpreadsheet (zip/xml и др.). Установить Oracle Instant Client.
  2. В корне выполнить composer install.
  3. Создать непубличный rjd_config.php с ключами из раздела Конфигурация; не коммитить.
  4. Убедиться, что Oracle baseline и нужные db migrations установлены, а пользователь имеет права на объекты/DBMS_SESSION.
  5. Дать процессу PHP запись в tmp/.
  6. Запустить: php -S 127.0.0.1:8082 router.php и открыть http://127.0.0.1:8082.

Apache / production

  1. DocumentRoot предпочтительно направить на public/; включить rewrite и HTTPS.
  2. Развернуть Composer dependencies без dev, локальный production config и OCI8/Instant Client.
  3. Настроить права только на tmp, запретить web-доступ к config/db/tmp/vendor.
  4. Для подпути согласовать base_path и web server.
  5. Для Kerberos mode=server настроить аутентификацию web server и проверенный REMOTE_USER.
  6. Проверить Secure cookie, debug=false, лимиты upload/post/memory, ротацию логов и backup Oracle.

Docker

Не подтверждёнВ текущем дереве нет Dockerfile или docker-compose. Поэтому воспроизводимой Docker-инструкции из репозитория не существует. Если контейнер используется вне Git, нужно отдельно зафиксировать образ PHP+OCI8, Instant Client, mounts config/tmp и web server.
Автозапуск рассылокПосле создания CLI worker предпочтительны systemd timer или cron, запускаемые от пользователя приложения с тем же config и правами к tmp. Нельзя вызывать защищённый web endpoint «для cron» без отдельной аутентификации и блокировки.

16. Типовые задачи

Добавить отчёт / колонку / фильтр

Отчёт: Registry → ApiController source/handler → routes → page settings/JS behavior → при необходимости mailing handler → проверить права/организацию/Excel.

Колонка: добавить key/label в detail columns реестра; убедиться, что key входит в SELECT/белый список API и реально возвращается Oracle; проверить сортировку и обе выгрузки.

Фильтр: добавить filter в реестр с правильными contexts и options/list key; обработать bind-условие в API; проверить page и mailing формы. Если фильтр не должен участвовать в рассылке, contexts=['page'].

Изменить Excel

Общие header colors/font/border/autosize/filter — ExcelStyle. Проверить ручную detail, summary, matrix и mailing XLSX. Рассылка формирует только Excel.

Добавить страницу или право
  1. Добавить code, label, routes, visibility и navigation metadata в PageRegistry.
  2. Реализовать controller + template и исполняемый route.
  3. Не добавлять отдельные массивы в middleware или меню: они читают реестр автоматически.
  4. Назначить право ролям в admin UI и проверить обычного пользователя/API.
Изменить структуру рассылки
  1. Создать forward migration и отдельно rollback; не редактировать уже выполненный DDL без новой версии.
  2. Обновить MailingService read/write/validation и controller/template.
  3. Если меняется результат — runner/manifest/style.
  4. Обновить admin journal и pagination.
  5. Протестировать существующую запись, новую, edit, active, delete, user/admin run, error run.
Найти источник конкретного значения
  1. Найти label/key в ReportConfig.
  2. Найти endpoint и handler в routes.php.
  3. В ApiController найти метод и его *From().
  4. Проследить alias до Oracle field/view, затем проверить DB package/view definition вне этого репозитория.
  5. Для производных значений проверить Claims, ReportService, WagonCargoState и SQL CASE.

17. Потенциально опасные места

РискПочемуБезопасное действие
Fail-open правОшибка role tables и отсутствие ADMIN пропускают запросПосле bootstrap перейти на fail-closed и мониторить миграции.
Неполный CSRFНет общего middlewareДля каждой mutation проверка; лучше централизовать.
Dynamic SQLgroup/order/fields собираются строкамиТолько registry whitelist; не подставлять пользовательский текст.
Импорт заменяет срезDELETE перед INSERTСохранять транзакцию, добавить preflight и lock; не выносить DELETE из transaction.
DDL drop/PURGEБез recycle binBackup, точная схема, change ticket, dry review.
Timezone fixНе идемпотентенЗапустить один раз и отметить версию миграции.
Report files/logsНет retention; адресаты и пути в manifest/DBПрава 0770, вне public, очистка, минимальный срок.
Большие отчётыВсе rows и workbook держатся в памятиЛимиты, streaming/chunking, измерение объёма.
Параллельные mailing runsНет lock/idempotencyДо scheduler добавить lease/unique run key.
SecretsЛокальный config содержит доступыНе коммитить/не логировать; secret store на production.

18. Устаревший, дублирующийся и неиспользуемый код

  • /bin/downloads_mail_rjd.php зарегистрирован в routes, но файла bin/downloads_mail_rjd.php в текущем проекте нет — маршрут завершится fatal/500 после авторизации.
  • Публичный /tmp/admin-mockup.html обслуживает временный макет, если файл появится. Для production такой маршрут лишний и создаёт риск публикации временного содержимого.
  • Маршруты нормативов и станций продублированы под /directories/* и /admin/directories/*.
  • 20261026_add_report_mailing_runs.sql дублирует треть структуры полного 20261026_report_mailings.sql; это альтернативные сценарии, не последовательные миграции.
  • Config keys auth_log_file, ldap_log_file, ad_debug загружаются, но просмотренные Auth/Ldap классы ими не пользуются.
  • Комментарий ImportController про «отдельную ручную страницу из bin» не соответствует текущему дереву.
  • GET /logout не завершает сессию, а лишь возвращает на login; реальный logout — POST с CSRF.
  • Тестового каталога и автоматических тестов в текущем проекте нет.
Не удалять автоматическиЭти места отмечены как кандидаты. Перед удалением проверьте внешние закладки, reverse proxy, эксплуатационные скрипты и production-ветку.

19. Рекомендации по улучшению

  1. Baseline БД и migration ledger: добавить полный versioned DDL всех реально используемых объектов и таблицу версии.
  2. Тесты: unit для Registry/validation/style, integration для Oracle repositories, smoke для routes и прав.
  3. Выделить repositories: перенести SQL из контроллеров, особенно монолитного ApiController.

  8. Наблюдаемость: структурированные логи, request/run IDs, ротация, метрики времени/строк/памяти.
