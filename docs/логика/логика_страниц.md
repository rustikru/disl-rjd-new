# Пользовательские KPI — группировка и детализация

Пользовательские KPI сохраняют условия в `XX_ETW.XX_RJD_KPI_TBL.WHERE_CONFIG`.
Для `TABLE` открывается стандартная детализация. Для группировки доступны только
фиксированные шаблоны `TRAIN_NUMBER` (по номеру поезда) и `TRAIN_INDEX`
(по индексу поезда). Их определения находятся в
`src/Reports/KpiGroupingTemplates.php`; в Oracle сохраняется только код шаблона
в `WHERE_CONFIG.detail.template`.

`ApiController::dislDetail()` применяет условия KPI, группирует вагоны по полю,
заданному шаблоном, и возвращает сводные показатели, маршрут и фиксированные
поля группы. Раскрытие карточки показывает агрегированные сведения о группе.
Нажатие на блок количества открывает общую табличную детализацию АСУ «Подход»
с сохранением `kpi_id` и условий KPI. Для ограничения выбранной группой
передаются `group_value` либо `group_value_is_null=Y`; API применяет поле
группировки из проверенного фиксированного шаблона. Сводные ссылки слева также
открывают эту общую таблицу, при необходимости с фильтром `cargo_state`.
В URL табличного режима используются `ctx=approach` или `ctx=departure`,
`_endpoint=/api/dislocation/detail` и `kpi_table=Y`. Отдельный упрощённый
рендерер таблицы для группы не используется.
Гружёность определяется `WagonCargoState::SQL_EXPRESSION`.

Старые конфигурации `GROUPED` с `group_field=train_no` и `train_index`
поддерживаются через совместимое сопоставление в
`KpiGroupingTemplates::fromDetail()`. Системные KPI не затрагиваются и сохраняют
стандартную или настроенную системную детализацию. Изменения схемы Oracle не
требуются; реальную выборку следует проверить на целевой БД.


## Управление KPI (SUPER)

Страница `/admin/kpi` доступна только системной роли `SUPER`. Право и URL
зарегистрированы в `src/Services/PageRegistry.php`, HTML и POST-маршруты
зарегистрированы в `src/routes.php`. Страница использует `KpiAdminController`
и шаблон `templates/admin/kpi.php`.

Системные KPI (`IS_SYSTEM = 'Y'`) можно редактировать только по полям `LABEL`,
`ORDER_BY`, `TREND_PERIOD`, `TREND_UNIT` и включать/отключать через `IS_ACTIVE`.
Код, тип и условия системного KPI остаются под управлением существующего PL/SQL.
Удаление системных KPI административной страницей не предусмотрено.

Пользовательские KPI (`IS_SYSTEM = 'N'`) можно редактировать через существующий
конструктор пользовательского KPI с административным признаком `admin=1`;
сервер разрешает такое редактирование только роли `SUPER`. Также доступны
отключение/включение и удаление. Все действия проверяют CSRF и записываются
в `XX_RJD_AUDIT_LOG` через `AuditLog`.

Признак `IS_ACTIVE` добавлен миграцией
`db/kpi/2026-11-06-kpi-admin-active.sql`. Миграцию необходимо применить в Oracle
до включения страницы. API сводных KPI и детализации исключает отключённые KPI.
