# Логика страниц и карточек KPI

Актуализировано по исходникам проекта 05.11.2026. Применение SQL-пакетов в установленной БД проверяется отдельно. Документ описывает реализацию, а не подтверждает соответствие всем требованиям МТФ.


Документ описывает текущую логику проекта. Все значения берутся из `XX_DISLOCATION_RJD`, а карточки KPI — из представления `XX_RJD_KPI_TBL_V`. Для пользователя дополнительно применяется фильтр организации из текущей сессии.

## Общие правила

Для каждой справки выбирается последняя дата `report_dt` нужного типа. Базовое условие выглядит так:

```sql
report_dt = TO_DATE(:report_dt, 'YYYY-MM-DD HH24:MI:SS')
AND type_reference = :type_reference
```

Для MTF дополнительно применяется ограничение по организации и исключаются служебные номера вагонов (`wagon_no` начинается с `0`) и записи с операцией `ИСКЛЮЧЕНИЕ ВАГОНА ИЗ ВАГОННОЙ МОДЕЛИ ДОРОГИ`.

## Карточки KPI

### Дашборд (`dashboard_kpi`)

| Код | Название карточки | Условие |
|---|---|---|
| `wag_cistern` | Вагоны-цистерны | Тип вагона после `fnc_mapping_wag_type(wagon_type_code)` равен `ЦС`. |
| `wag_others` | Остальные вагоны | Тип вагона после `fnc_mapping_wag_type(wagon_type_code)` не равен `ЦС`. |
| `loaded_transit` | Гружёный транзит | Пункт назначения не содержит `УГЛ`, станция операции отличается от пункта назначения, `cargo_weight_kg > 0`. |
| `comming_to_ugl` | Подход к УГЛ | Пункт назначения содержит `УГЛ`, станция операции отличается от пункта назначения. |
| `arrived_today_ugl` | Прибыли на УГЛ сегодня | Пункт назначения содержит `УГЛ`, станция операции равна пункту назначения, дата `oper_dt` — сегодня. |

```sql
-- пример
dest_station NOT LIKE '%УГЛ%'
AND dest_station <> oper_station
AND cargo_weight_kg > 0
```

### Отправление вагонов (`departue_kpi`)

| Код | Название карточки | Условие |
|---|---|---|
| `eysk` | Ейск | `dest_station` содержит `Ейск`. |
| `zabaykalsk` | Забайкальск | `dest_station` содержит `Забайкальск`. |
| `luzskaya` | Лужская | `dest_station` содержит `Лужская`. |
| `abandoned_trains` | Брошенные поезда | `type_reference = 'Отправка'` и операция содержит `БРОСАНИЕ ПОЕЗДА НА СТАНЦИИ`; либо операция пустая, а `wagon_state` содержит `БРОШЕН`. |

```sql
type_reference = 'Отправка'
AND (
    UPPER(NVL(operation, ' ')) LIKE '%БРОСАНИЕ ПОЕЗДА НА СТАНЦИИ%'
    OR (TRIM(operation) IS NULL AND UPPER(NVL(wagon_state, ' ')) LIKE '%БРОШЕН%')
)
```

### Подход вагонов (`approach_kpi`)

| Код | Название карточки | Условие |
|---|---|---|
| `eysk` | Ейск | `depart_station` содержит `Ейск`. |
| `zabaykalsk` | Забайкальск | `depart_station` содержит `Забайкальск`. |
| `luzskaya` | Лужская | `depart_station` содержит `Лужская`. |
| `delivery_time` | Нарушен срок доставки | `type_reference = 'Подход'`, календарная дата справки `TRUNC(report_dt)` больше нормативного срока `TRUNC(norm_delivery_dt)`, `trip_end_dt` не заполнена, станция операции не содержит `Угле`. |
| `abandoned_wagons` | Брошенные поезда | `type_reference = 'Подход'` и операция содержит `БРОСАНИЕ ПОЕЗДА НА СТАНЦИИ`; либо операция пустая, а `wagon_state` содержит `БРОШЕН`. |
| `formed_trains` | Сформированные поезда | `type_reference = 'Подход'`; начальный цифровой индекс `train_index` заканчивается на `68207` либо текст содержит `УГЛЕУРАЛЬСКАЯ`, `БЕРЕЗНИКИ`, `КИЗЕЛ` или `ЗАЯЧЬЯ ГОРКА`. |

```sql
TRUNC(report_dt) > TRUNC(norm_delivery_dt)
AND trip_end_dt IS NULL
AND UPPER(oper_station) NOT LIKE '%УГЛЕ%'
AND type_reference = 'Подход'
```

### Погрузка (`loading_kpi`)

Карточки определяются кодом из таблицы KPI. Сейчас поддерживаются:

| Код | Название карточки | Период по `trip_start_dt` |
|---|---|---|
| `loading_today` | Погружено сегодня | от начала текущего дня до начала следующего дня; |
| `loading_yesterday` | Погружено вчера | предыдущий календарный день; |
| `loading_month` | Погружено за месяц | с первого дня текущего месяца до начала следующего дня. |

Общая выборка погрузки:

```sql
type_reference = 'Отправка'
AND trip_start_dt IS NOT NULL
AND TRIM(wagon_no) NOT LIKE '0%'
AND operation NOT LIKE '%ИСКЛЮЧЕНИЕ ВАГОНА ИЗ ВАГОННОЙ МОДЕЛИ ДОРОГИ%'
-- для MTF: depart_station начинается с «Углеуральская»
```

Подсчёт карточки выполняется как `COUNT(CASE WHEN <условие периода> THEN 1 END)`.

## Страницы и условия выборки

### Отправка / Отправление вагонов

В коде страница называется «Отправление вагонов», а в БД тип справки — `Отправка`.

```sql
type_reference = 'Отправка'
AND dist_remain_km > 0
-- для MTF:
AND REGEXP_LIKE(UPPER(TRIM(depart_station)), '^УГЛЕУРАЛЬ?СКАЯ([[:space:]]|$)')
```

Также доступны фильтры по `cargo_name`, `dest_station`, номеру вагона, группировке по дороге/станции отправления и колонкам типа вагона/груза. Исключённые вагоны удаляются отдельным реестром.

### Подход вагонов

```sql
type_reference = 'Подход'
AND dest_station LIKE '%УГЛ%'
AND TRIM(wagon_no) NOT LIKE '0%'
AND operation NOT LIKE '%ИСКЛЮЧЕНИЕ ВАГОНА ИЗ ВАГОННОЙ МОДЕЛИ ДОРОГИ%'
```

Для MTF используется пункт назначения с `УГЛ`. Есть фильтры по `cargo_name`, `prev_cargo`, номеру вагона и исключению станции операции. Группировка — по дороге или станции назначения.

### Простои

Сначала берутся последние записи типов `Подход` и `Отправка`, затем остаются вагоны, прибывшие на станцию назначения:

```sql
dist_remain_km = 0
AND UPPER(TRIM(oper_station)) = UPPER(TRIM(dest_station))
AND TRIM(wagon_no) NOT LIKE '0%'
AND operation NOT LIKE '%ИСКЛЮЧЕНИЕ ВАГОНА ИЗ ВАГОННОЙ МОДЕЛИ ДОРОГИ%'
```

На основании `trip_end_dt` и текущей даты вычисляются фактический простой и группа простоя. Можно фильтровать по станции назначения и длительности простоя.

### Погрузка

Страница использует справку `Отправка`, но выбирает только строки с датой начала рейса:

```sql
type_reference = 'Отправка'
AND trip_start_dt IS NOT NULL
AND TRIM(wagon_no) NOT LIKE '0%'
AND operation NOT LIKE '%ИСКЛЮЧЕНИЕ ВАГОНА ИЗ ВАГОННОЙ МОДЕЛИ ДОРОГИ%'
```

Для MTF добавляется станция отправления `Углеуральская`. Фильтры страницы: период погрузки, груз и номер вагона.

## Где искать реализацию

- `src/Controllers/ApiController.php` — построение условий страниц и периодов погрузки (`approachFrom`, `departureFrom`, `loadingFrom`, `downtimeFrom`).
- `db/XX_RJD_DISLOCATION_NEW_PKG.pkb` — условия KPI (`get_kpi_where`) и расчёт подписей/значений карточек.
- `public/assets/js/app.js` — запросы карточек и переход в детализацию.
- `XX_RJD_KPI_TBL_V` — список карточек, их коды, названия и порядок.

При добавлении новой карточки нужно добавить запись в таблицу KPI и явно добавить её условие в `get_kpi_where` (для обычных KPI) либо в `loadingPeriodCondition` (для карточек погрузки).

## Расчёт и переходы KPI

Для всех обычных KPI из таблиц выше условие задаёт `db/XX_RJD_DISLOCATION_NEW_PKG.pkb::get_kpi_where()`. API карточек — `kpiSummary()`; основной вызов пакета — `get_kpi_row()`, запасные — `set_kpi_label()`, `fnc_get_kpi_trend_pct()`, `fnc_get_kpi_trend_dir()`. Для погрузки используются `loadingKpiSummary()` и `loadingPeriodCondition()`.

Обычный подсчёт — количество записей. Для `formed_trains` считаются уникальные обрезанные индексы. Для `abandoned_trains` — уникальные сочетания индекса (при отсутствии — номера поезда или вагона) и станции. Для `abandoned_wagons` остаётся подсчёт вагонов, несмотря на новое отображаемое название.

Список карточек, коды и порядок — `XX_RJD_KPI_TBL_V`. Переходы — `public/assets/js/app.js::kpiCards()` и обработчик клика KPI. Стандартная детализация — `templates/detail.php`.

### Промежуточная детализация поездов

Определения — `ReportConfig::kpiDetail()`: название, поля, форматы, группировка, секции счётчиков и фильтры. Подписи полей берутся из `source-columns.php`. Сервер получает код KPI по ID из БД; выборка выполняется в `ApiController::dislDetail()`. Шаблон отображает `group_config`, полученный вместе с группами.

| Код режима | KPI | Группировка | Переход |
|---|---|---|---|
| `abandoned-trains` | `abandoned_wagons`, `abandoned_trains` | Индекс, номер, станция, дорога, дата операции | Отдельно гружёные и порожние |
| `formed-trains` | `formed_trains` | Индекс поезда | Все вагоны группы |

Гружёность определяется через `src/Services/WagonCargoState.php`: вес больше нуля; для платформ — больше 12 000 кг. Даты отображаются как ДД.ММ.ГГГГ ЧЧ:ММ:СС. У сформированных поездов нет шкалы и простоя. Для описательных полей текущая SQL-выборка использует MAX, для начала рейса — MIN; разные операции получают подпись «Разные операции». Это агрегаты группы, а не гарантированно одна исходная строка.

### Сортировка сводных

`summaryRowOrder()` задаёт приоритет России по стране назначения и Свердловской по дороге назначения. Правило применяется общим `summaryReport()`, если не передан отдельный порядок. Поэтому область действия шире двух страниц.

## Доступ к данным

`PageRegistry` и middleware проверяют страницы и API. Детализация защищена правом `wagon-detail`. Oracle VPD `RJD_DATA_SCOPES` использует `XX_RJD_DISLOCATION_NEW_PKG.DATA_SCOPE_PREDICATE`; ID пользователя передаётся через CLIENT_INFO, организация — через CLIENT_IDENTIFIER. Без пользовательского контекста политика возвращает пустую выборку. Подробности — [области данных](../../db/data_scopes/README.md).

## Известные расхождения с требованиями МТФ

- Просрочка сравнивается с датой операции, а не с текущей датой/датой справки; нет требуемой проверки отсутствия окончания рейса.
- Прибытие сегодня использует дату операции вместо АСОУП с подстановкой окончания рейса. Отдельное условие прибытия вчера в проверенном пакете не найдено.
- Для сформированных поездов учитываются начальный цифровой индекс с окончанием `68207` и текстовые назначения `УГЛЕУРАЛЬСКАЯ`, `БЕРЕЗНИКИ`, `КИЗЕЛ`, `ЗАЯЧЬЯ ГОРКА` в `train_index`.
- Для Ейска и Забайкальска нет промежуточных групп по поездам.
- Брошенные поезда группируются по пяти полям, поэтому один индекс может дать несколько блоков; отбор дополнительно допускает пустую операцию со статусом «БРОШЕН».
- Условия KPI и страниц не полностью совпадают. Нельзя считать, что KPI автоматически наследует выборку страницы.
- Требования к отправлению на предоставленных скриншотах обрезаны; полное соответствие не подтверждено.

Личные карточки пока описаны как план: [личные KPI](../доработки/personal-kpi-cards.md).
