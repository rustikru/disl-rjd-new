# Диагностические SQL-скрипты

Скрипты предназначены для Oracle и только читают данные. Они не изменяют
таблицы, package или настройки приложения.

Запускать под владельцем схемы `XX_ETW` в SQL Developer, SQLcl или SQL*Plus.

- `oracle-health.sql` — невалидные объекты, ошибки компиляции и состояние
  основных объектов проекта.
- `kpi-check.sql` — карточки KPI, некорректные настройки, персональное скрытие и
  проверка расчёта системных KPI.
- `reference-check.sql` — последние справки РЖД, дубли и качество исходных
  данных.
- `users-access-check.sql` — пользователи, роли, группы доступа и организации.
- `pages-check.sql` — права ролей на страницы и глобально отключённые страницы.
- `sessions-audit-check.sql` — активные сессии и журнал административных действий.
- `mailings-check.sql` — настройки рассылок, отчёты и история запусков.
- `data-scopes-check.sql` — области данных, правила и назначения пользователям.
- `table-layouts-check.sql` — персональные колонки таблиц и повреждённые раскладки.
- `password-resets-check.sql` — состояние запросов восстановления пароля.
- `directories-check.sql` — станции, нормативы претензий и контроль простоев.

Перед запуском файлов с параметрами замените значения в блоке `DEFINE`.
`organization_id` можно узнать первым запросом соответствующего скрипта.

Если запрос завершается `ORA-00942`, значит объект ещё не создан в этой схеме
или у пользователя нет права чтения. `ORA-04063` и `ORA-06508` обычно означают,
что package или зависимый объект не скомпилирован — сначала выполните
`oracle-health.sql`.

Файлы специально разделены по модулям: можно запускать только диагностику
проблемного раздела, не выполняя весь набор.
