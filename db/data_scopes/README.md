# Области данных

Выполнить `01_tables.sql` один раз от имени владельца схемы Oracle (12c+).
Право `data-scopes` назначить нужной административной роли через форму роли.
SUPER получает доступ автоматически. Права автоматически другим ролям не выдаются.

Раздел: `/admin/data-scopes`. Назначения — в форме создания/редактирования
пользователя; менять их может SUPER или ADMIN с правом `data-scopes`.
Пустые назначения разрешены для подготовки конфигурации.

Одна строка правила: организация AND груз AND станция назначения AND вагон.
Пустые дополнительные поля означают любые значения. Поэтому разрешающая строка
с одной организацией означает полный доступ ко всем её грузам.
Разрешения объединяются OR, затем исключаются все совпавшие DENY всех областей.
Учитываются только активные области с действующим периодом (границы включены).

Для включения выполнить `01_tables.sql`, затем `03_indexes.sql`, скомпилировать
`../XX_RJD_DISLOCATION_NEW_PKG.pks` и `../XX_RJD_DISLOCATION_NEW_PKG.pkb`,
затем выполнить `02_access_policy.sql`. Фильтр находится в функции
`XX_RJD_DISLOCATION_NEW_PKG.DATA_SCOPE_PREDICATE` основного пакета.
Политика Oracle VPD ограничивает SELECT таблицы XX_DISLOCATION_RJD, включая
основной пакет, API, Excel и рассылки. Требуется поддержка DBMS_RLS данной
редакцией Oracle и право EXECUTE на пакет. Аккаунты SYS и EXEMPT ACCESS POLICY
обходят VPD и не должны использоваться приложением.
Пользователь передаётся через CLIENT_INFO при создании соединения; рассылки
исполняются от владельца рассылки и восстанавливают контекст после завершения.
Пользователь без разрешений получает пустую выборку; SUPER — полный доступ.
CLIENT_IDENTIFIER пока продолжает хранить организацию. Его смысл не изменён.
Справочник площадок и привязка площадок к продуктам требуют отдельного подключения;
сейчас доступ задаётся напрямую кодами грузов в составных правилах.

SQL не изменяет существующие назначения организаций и ролей и не заполняет
автоматически области существующим пользователям.

Перед включением назначить области существующим пользователям. Сравнить планы
и время реальных отчётных запросов до и после включения на копии данных.
Фильтр использует EXISTS/NOT EXISTS, без PL/SQL-вызовов на каждый вагон.
Извлечение кодов из текстов справки может влиять на время; производительность
без замеров не гарантируется. Существующий выбор одной организации сохраняется:
область не объединяет организации на экране автоматически.
